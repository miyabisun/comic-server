# リマスター検証記録

2026-09-09、AMD Ryzen 7 PRO 4750GE / Linux x86-64、CPU推論2スレッドで確認。
本番コレクションは使用していない。日本語の小さい文字、細線、網点、白黒の均一な塗り、
カラーの文字・線・塗りを含む800×1200の生成ページをJPEG品質65で劣化させた。
これは代表要素を分離した検証であり、すべての漫画・画風に対する品質保証ではない。

## 品質

| 対象 | 入力 | リマスター結果 |
|---|---|---|
| 白黒 | [原寸入力](remaster-samples/mono-input.jpg) | [原寸結果](remaster-samples/mono-result.png) |
| カラー | [原寸入力](remaster-samples/color-input.jpg) | [原寸結果](remaster-samples/color-result.png) |

- 小さい日本語文字は判読でき、文字列と主な線の形を保持した。線の階段状の輪郭が完全に
  消えるわけではないが、圧縮ノイズの周辺が整理される。OCRによる正答率は測っていない。
- 網点の配列は保持されたが、点の形や濃さは変わる。白黒モデルは均一な灰色の楕円にも細かい
  網点を生成した。これは原本の厳密な復元ではなく、モデルの学習した漫画表現による再構成。
- カラーモデルでは青い文字、赤系の細線、橙色の塗りを保持した。点や線のコントラストは変化する。
  色を含むページを白黒モデルへ渡さない、保守的な判定も単体テストで確認した。
- 出力は1600×2400。ただし寸法の増加だけを品質合格の理由にはしていない。
  原本を保存し、上の比較から用途に合うか確認できる構成にした。

## 時間とメモリ

| ページ | モデル | 経過時間 | 最大RSS |
|---|---|---:|---:|

| カラー | 2x IllustrationJaNai V1 ESRGAN 120k | 97.53秒 | 416,980 KiB（407.2 MiB） |

各1回の実測値。モデル読込みとPNG保存を含み、画像サイズ・CPU・同時負荷に依存する。
ページ単位の別プロセス、128pxタイルと32pxの周辺領域でメモリを制御する。
1冊の処理はページ数にほぼ比例するため、即時に完了する操作ではない。

## 変換と分割推論

公式V1のFP16重みをFP32 ONNX opset 17に変換した。採用した8モデルすべてについて、
64×64と80×96の入力で元のPyTorch推論と比較。出力を同じく0〜1へ制限した際の最大誤差は
0.00000864以下だった。変換スクリプトは0.0001を超える差で失敗する。

分割推論はフレーム全体の推論と完全には一致しない。256×256の文字・網点を含む入力で、
Rustの分割出力と全体を一度に通したONNX出力を比較したところ、8bit画素値換算で
平均絶対差0.03695、最大差10.99、タイル境界付近の平均差0.18287だった。
大きな継ぎ目は目視で確認されなかったが、細部の差はある。必要なら周辺領域を増やし、
時間・メモリとともに再測定する。奇数寸法65×63も処理でき、130×126で保存されることを確認した。

## アプリケーションの保全と操作

Bunの隔離テストで原本保持、別作品への登録、同名衝突、名前変更後の再実行、
リマスター版の再処理拒否、推論失敗、実行中の子プロセス中止、登録失敗時のロールバックを確認した。
作業領域への通常・URLエンコード経由の画像要求は403となる。

実際のDockerイメージでも、Rust・同梱モデル・ONNX Runtimeでページを処理し、
リマスター版の登録とPNGのHTTP配信を確認した。原本はバイト単位で不変。
サーバーの強制終了後も原本と完成済みの登録は保持され、未完成の作品は公開されなかった。
Rust単体でも親のstdin pipeが閉じると処理を停止すること、EXIF回転を反映することを確認した。
この小さい入力の処理中に一覧APIを取得した際の応答は約1.9msだった。

Chromium + Playwrightで、情報ダイアログからのキーボードによる開始、進捗、完了リンク、
Escでの終了を確認した。明暗テーマ、390px/1440px幅、中止・失敗・未設定、
ダイアログ内の操作と終了時のフォーカス復帰、36px以上の操作領域、横溢れがないことも確認した。UI状態の検証では制御したAPI応答を使い、実推論の検証とは分けた。

## 再現

READMEのモデル準備を終え、`ORT_DYLIB_PATH`を設定する。Linuxのfontconfigと日本語フォント、
ビルド用Python環境のPillowを使用する。出力先は存在しない専用directoryを指定する。

```bash
bun run test
cargo build --release --locked
/tmp/comic-model-build/bin/python remaster/verify.py mono /tmp/comic-remaster-mono
/tmp/comic-model-build/bin/python remaster/verify.py color /tmp/comic-remaster-color
```

生成した入力・出力・計測JSONが各directoryへ保存される。検証スクリプトは出力寸法と、
256px領域の全体推論との平均差（8bit換算1未満）も検査する。生成ページの比較で得た結論を、
未確認の実作品やGPUの性能・品質へ一般化しない。
